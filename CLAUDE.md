# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install dependencies
uv sync

# Rebuild public Parquet files from private data (requires data_private/)
uv run python -m analysis

# Render the site (Quarto must be installed, or use CI)
uv run quarto render site/

# Preview the site locally
uv run quarto preview site/
```

Quarto is not installed locally — the CI/CD pipeline handles rendering. Use `quarto preview site/` if you install it manually.

## Architecture

This is a **privacy-aware personal finance data story**: a static site generated by Quarto that combines Python-rendered narrative charts with browser-side interactive exploration.

### Data pipeline

`data_private/` (gitignored) → `analysis/build_public_data.py` → `data_public/*.parquet`

The pipeline reads raw private transactions, applies a random scale factor (0.5–2.0) for privacy, aggregates to monthly totals, and writes three Parquet files:
- `expenses_monthly.parquet` — 7-col flow schema, 2345 rows
- `income_monthly.parquet` — same schema, 370 rows, values negative
- `events_public.parquet` — 11 hardcoded life milestones

Flow schema (shared): `date, flow_type, source, destination, sub_category, category, value`

### Site structure

`site/` contains the Quarto project. Key relationships:
- `site/_pre-render.py` runs before each render: creates `site/data_public` as a symlink to `../../data_public`, then copies Parquets into `_site/data_public/` so the browser can fetch them
- `site/story/index.qmd` imports `analysis.story_charts` and renders static Plotly figures (cached via `freeze: auto`)
- `site/explore/index.qmd` is mostly HTML scaffolding; all interactivity is in the JS modules

### JavaScript modules (`site/assets/js/`)

All browser-side logic uses DuckDB-Wasm v1.29.0 (from CDN) to query the Parquet files directly in the browser — no backend.

- **`duckdb_init.js`** — Singleton that fetches the 3 Parquets and registers them as DuckDB tables (`expenses_monthly`, `income_monthly`, `events_public`). All other modules call `getConnection()` or `runQuery()` from here.
- **`explore_charts.js`** — Category-over-time line chart with checkbox filters and moving average slider. Queries `expenses_monthly`.
- **`sankey.js`** — Sankey diagram with a time-series brush for date-range selection. Handles income/expense toggle and sub-category → category mapping.
- **`sql_playground.js`** — Freeform SQL editor with recipe templates that execute against all 3 tables.

### Python package (`analysis/`)

- `schemas.py` — Polars schemas and all valid categorical values (constants); source of truth for category names
- `story_charts.py` — Plotly chart functions called from `story/index.qmd`; `get_expenses_by_category()` and `get_events()` return lists of dicts for `ojs_define`
- `build_public_data.py` — Data pipeline (run via `python -m analysis`)

### Deployment

GitHub Actions (`.github/workflows/publish.yml`) on push to main:
1. `uv sync`
2. `quarto render site/`
3. Deploy `site/_site/` to GitHub Pages

The `_freeze/` directory is committed so CI doesn't need to re-execute Python cells.
